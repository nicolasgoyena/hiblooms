# HIBLOOMS — Detection and monitoring of cyanobacterial blooms in reservoirs

Repository of the digital tool of the **HIBLOOMS** project (Instituto BIOMA, University of Navarra).
It combines **Sentinel-2** imagery (Google Earth Engine) with field, laboratory and buoy data
to monitor water quality in reservoirs.

Live version: <https://hiblooms.onrender.com> (interface in Spanish and English)

## What it does

- **Project**: project information, team and funding.
- **Current monitoring**: status of all reservoirs (hydrological bulletin, near-real-time El Val buoy).
- **Satellite viewer**: Sentinel-2 image search by reservoir, index maps, time series,
  class distribution and historical context. Accepts custom shapefiles (ZIP) for any reservoir.
- **Project data**: field sampling, laboratory, probes and campaigns (PostgreSQL/PostGIS database).
- **Models and calibrations**: cards of the validated models and calibration with the user's in situ data.

## Models

Models with fitted coefficients live in `data/models/*.json` (formula, coefficients, validation and
limitations), not in the code: recalibrating a model does not require touching Python.

| Index | Status | Reservoir |
|---|---|---|
| `Chla_Val_cal` — chlorophyll-a | Validated (CHE buoy, 2018–2024, leave-one-year-out validation) | El Val |
| `PC_Bellus_cal`, `Chla_Bellus_cal`, `SDD_Bellus_UV`, `TSM_Bellus_UV` | Universitat de València models | Bellús |
| `PC_Val_cal`, `UV_PC_Gral_cal`, `PCI_B5/B4` | Experimental (Sentinel-2 does not estimate phycocyanin reliably) | — |
| `NDCI_ind`, `MCI` | Spectral indices | Any |

The analyses behind these decisions are in `analysis/` (see below).

## Run locally

```bash
# Backend (from the repo root)
pip install -r web/backend/requirements.txt
export GEE_SERVICE_ACCOUNT_JSON=/path/to/service_account.json   # or the JSON as text
export DATABASE_URL=postgresql://user:password@host:5432/db      # optional (Data tab)
uvicorn web.backend.server:app --reload --port 8000

# Frontend
cd web/frontend
npm install
npm run dev      # http://localhost:5173
```

Without GEE credentials the backend starts in **demo mode** with simulated data
(`HIBLOOMS_MOCK=1` forces it). On Windows, `web\start.bat` launches both parts.

## Deploy

```bash
docker build -t hiblooms .
docker run -p 8000:7860 -e GEE_SERVICE_ACCOUNT_JSON="$(cat gee_key.json)" hiblooms
```

Environment variables: `GEE_SERVICE_ACCOUNT_JSON`, `DATABASE_URL` (read-only), `HIBLOOMS_USERS`
(`user:password,...`), `HIBLOOMS_SECRET`, `HIBLOOMS_DATA_DIR`. Details in `DEPLOYMENT.md`.

## LifeWatch ERIC component

The HIBLOOMS workflow in the LifeWatch VRE (*HiBloomsCalibration* and *HiBloomsVisualization*
components) is maintained in the LifeWatch GitLab and takes `hiblooms_core.py`,
`web/backend/calibration.py` and `data/models/` from this repository as its reference.
